The problem

Every agent remembers alone

Each agent keeps its lessons in its own file, on one machine. So you repeat the same correction per agent and per computer, and the files grow into rulebooks loaded on every request.

01

One memory per tool

Nothing an agent learns reaches the others.

  • OpenCodeAGENTS.md · ~/.config/opencode

One memory per machine

Your laptop's agent has no idea what your desktop's agent learned yesterday, and nothing records why a rule exists or whether it still holds.

How it works

What happens while you work

You keep correcting agents the way you already do. lrdmem turns those corrections into rules, weighs the evidence, and puts each rule in front of the agent when it matters.

Correct

You tell the agent it got something wrong, in chat or in a PR review. The skill records it with lrdmem learn, active right away.

Record

What happened becomes an experience: written once, never edited, with the agent, device and files. Hooks also record every check that passes or fails.

Consolidate

At the end of each task, evidence promotes candidates, refutes contest them, duplicates merge, and anything that needs judgment waits in a queue.

Recall

Before an edit or command, hooks inject only the active memories whose triggers match. Obligations run as approved checks.

Install

Or install it by hand

One CLI per machine, one store for all of them. Connect each agent with its plugin or with lrdmem install, not both.

pipx install lrdmem                       # or: uv tool install lrdmem
git init ~/agent-memory
mkdir -p ~/agent-memory/{_global,work/my-app}
touch ~/agent-memory/{_global,work/my-app}/MEMORY.md
lrdmem config set store ~/agent-memory
lrdmem config set device notebook

A repo takes part when the store has a folder named after it (work/my-app/). Every worktree of the repo shares it.

claude plugin marketplace add larodiel/lrdmem
claude plugin install lrdmem@lrdmem

# or, without the plugin:
lrdmem install --agent claude --dry-run
lrdmem install --agent claude

The plugin carries the hooks and the skill and calls the installed lrdmem. Set LRDMEM_BIN if it is not on PATH.

codex plugin marketplace add larodiel/lrdmem
codex plugin add lrdmem@lrdmem
# then trust the hooks in /hooks

# or, without the plugin:
lrdmem install --agent codex
lrdmem install --agent opencode --dry-run
lrdmem install --agent opencode

Copies the plugin to ~/.config/opencode/plugins/lrdmem.js and the skill to ~/.config/opencode/skills/lrdmem.

Why it works

Built for what makes agents forget

Right memory, right moment

Triggers on file globs, commands and repos. Editing src/Service.php brings the PHP rules, not your whole rulebook.

Obligations are checks

"Always run phpcs" becomes a command the hook runs for the agent, after you approve its exact text. A failure blocks the end of the task.

Every rule remembers why

lrdmem why shows the experiences behind a rule: what went wrong, which agent, which device, when.

Evidence, not repetition

A candidate becomes active only with independent support from other agents, devices or days. Guessed causes stay hypotheses.

Plain Markdown in git

Read, edit, review and revert every memory. Each change is a revision; every automatic commit follows Conventional Commits.

Zero dependencies

Python 3.11+ standard library only. No server, no account, no telemetry. Hooks answer in about 100 ms.

plugins/shop-frontend-auth   (worktree) ├─▶ shop-frontend
plugins/shop-frontend-cart   (worktree) ┘

~/agent-memory/
├── _global/              about you, everywhere
└── work/                 an environment
    ├── _global/          every repo of work
    └── shop-frontend/    this repo
        ├── *.md          memories
        ├── experiences/  what happened
        ├── edges/        relations
        └── revisions/    every change

The repo key is the main checkout's directory name, from git rev-parse --git-common-dir. No per-project setup.

Sync across machines

It's git, so it travels

Every computer works on its own clone. lrdmem pulls at session start and pushes at the end of a task, or whenever you run lrdmem sync.

01

Track it in a private repo

cd ~/agent-memory
git remote add origin git@github.com:you/agent-memory.git
lrdmem config set device desktop
lrdmem sync
02

Clone it on the next machine

git clone git@github.com:you/agent-memory.git ~/agent-memory
lrdmem config set store ~/agent-memory
lrdmem config set device notebook
lrdmem config autopush on

Evidence from two machines counts as independent, which is what promotes a lesson to an active rule. Approved check commands never travel: each computer approves its own.

Safe by default

A memory agents write to is an attack surface

  • No secrets, ever. Every write refuses passwords, API keys, tokens and private keys, even JSON-escaped.
  • Commands run only after you approve them. By the hash of their exact text, per device.
  • File names are arguments. Never spliced into a shell string.
  • PR comments from your team only. Owners, members and collaborators of your own remotes.
  • Store content is untrusted. Git hooks, fsmonitor and submodules are off for every store call.
  • No surprise pushes. Autopush is opt-in; sync never force-pushes or autostashes.
  • Memory is data, not instructions. Injected text says so, stripped of control characters.
  • Reversible install. Backs up what it edits and keeps hooks it didn't write.

FAQ

Questions

Does anything leave my machine?

Only what you push with git, to remotes you chose. No server, no account, no telemetry. Hooks never push unless you turn autopush on.

Does it cost anything or call a model?

No. lrdmem runs no model: consolidation, search and recall are plain code over files. The agents you already use write and read the memories.

I already have CLAUDE.md and AGENTS.md. Do I drop them?

No. Keep project setup and always-true instructions there. Move the lessons that apply to some files or commands into lrdmem, where they show up only when they matter and keep the history of why.

Can my team share memories?

Yes. Make the team's environment its own git repo and link it into each person's store. Check commands from a shared memory still run only after each person approves them on their own computer.

What if an agent writes something wrong?

Memories an agent proposes start as candidates and need independent evidence to become active. Feedback flags bad ones, consolidation contests refuted ones, and lrdmem revert undoes any recorded change.

What if lrdmem isn't installed where the hooks are?

The hooks find no CLI and stay silent. The agent is never blocked.
